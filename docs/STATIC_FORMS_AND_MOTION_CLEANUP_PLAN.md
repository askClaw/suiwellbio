# 静态表单与新闻动效注册修复方案

状态：已实施并完成回归，结果见 `STATIC_FORMS_AND_MOTION_CLEANUP_RESULT.md`。针对提交 `1a522d5` 的两项 code review 发现。

## 1. 范围与约束

- 修复静态表单在脚本不可用时的原生提交，以及新闻列表替换后的动效引用残留。
- 保留表单布局、前端校验、FAQ渐进展开与草稿、新闻分类/页码/历史状态、现有入场节奏。
- 本轮仍不接后端，不新增持久存储；不包含提交commit或发布。
- 修改生成器与源脚本，再构建根目录HTML；不单独手改生成页面。

## 2. P2：静态表单默认不可提交

涉及：`scripts/build-pages.mjs`、`pages.js`、必要的 `pages.css`、生成的 `contact.html` 与 `service.html`。

### 默认HTML

1. 联系表单与每条FAQ反馈表单的输入、文本域、评价选项及按钮默认带 `disabled`，为需要脚本启用的控件增加统一标记。只处理这两类表单，不影响搜索、菜单或其他页面按钮。
2. 使用控件自身的禁用属性，避免增加fieldset包裹后改变现有grid/flex布局。
3. 保留静态提示，增加无脚本说明和可用的电话/邮箱入口；FAQ正文仍可使用原生details阅读。
4. 禁用状态应清楚可辨认；正常脚本初始化后恢复现有外观，不改变卡片和表单高度。

### 初始化顺序

1. 为当前表单先绑定同步执行的提交处理器，第一行即阻止原生提交。
2. 绑定校验、演示码刷新、意见展开和本页反馈记录逻辑。
3. 当前表单初始化成功后，才启用该表单带标记的控件，并标记ready状态。
4. 若初始化中途失败，尚未就绪的表单保持禁用。已经启用的表单必须已经具备提交拦截，不能出现“按钮已启用、监听器尚未绑定”的时间窗。
5. 启用操作仅作用于本次默认禁用的控件，不能顺带启用其他业务上原本应禁用的元素；不清空浏览器恢复的值或用户草稿，不重置已有评价。

### 验收

- 脚本正常：联系信息校验、错误演示码、刷新演示码、FAQ两种评价及补充意见均可用，提示仍明确没有发送。
- 脚本被移除/入口加载失败：控件不可输入和提交，电话/邮箱入口可用；FAQ正文可展开；URL不出现姓名、电话、邮箱、评价等查询字段。
- 延迟加载：脚本初始化前不可提交，初始化后才可用。
- 正常提交和按Enter操作均不导航、不增加查询参数，也不产生表单请求。
- 使用虚构测试值，检查iframe导航和本地请求记录；不能只断言按钮有disabled而不覆盖脚本失败状态下的行为。

说明：默认disabled解决用户交互和脚本初始化失败的退化路径，不以抵御主动篡改页面或另行编写提交脚本为目标。仅改变method或设置空action不能解决原生提交问题。

## 3. P3：释放动态新闻卡片的动效注册

涉及：`common.js`、`pages.js`；可新增一个小型注册生命周期模块及其单元测试。

### 状态与所有权

1. 将可枚举的注册表限制为pending/running目标；已完成目标使用 `WeakSet` 记录身份，继续防止同一个节点重复入场。
2. 不直接用WeakMap替换现有Map：后台恢复、减少动态效果、焦点处理需要枚举活动目标。
3. `completeEntrance` 仍然负责显示终态、写入完成状态和取消观察，同时从活动Map删除节点、写入完成WeakSet。首次注册即完成、正常动画结束、焦点强制显示、后台结算等路径均使用同一完成逻辑。
4. 活动Map删除元素后，既有settle遍历必须仍能完整处理其他目标；不要依赖已完成节点长期留在Map内。

### 动态列表销毁

1. 提供限定容器的注销函数；新闻render在替换 `#news-results` 内容之前调用。
2. 对容器内注册过的目标取消观察、取消以该节点为key的入场动画、删除活动注册及完成身份标记。清除入场临时类和状态，避免节点复用时遗留隐藏。
3. 覆盖pending、running与complete三类目标；入口清理幂等，容器没有注册目标时可安全调用。
4. 使用现有动画控制器取消任务，使旧finished回调失效。已经排队的IntersectionObserver回调在找不到活动状态时直接忽略，不能重新注册或更新旧节点。
5. 替换后仅注册新卡片；分类切换、页码切换、popstate和首次替换构建时卡片都走同一render流程。
6. 清理范围限定在结果容器，不影响导航、标题、其他页面目标或首页设备动画。

### 测试设计

- 若为可测试性抽取注册表，只抽取活动/完成身份及注销生命周期，不重写入场时间、分组、观察阈值和共用动画控制器。
- 单元测试使用真正的注册生命周期实现，注入观察器/取消回调，验证完成后活动数归零、重复完成/注销安全、三类节点注销、过期回调忽略、重新注册同节点的规则。
- 浏览器测试连续切换新闻分类100次，再执行前进/后退；检查正确内容、URL、可见状态和键盘操作。注册表计数由生命周期单元测试直接验证，不在生产window增加调试全局变量。
- 在旧卡片待入场和动画运行期间触发替换，确认没有旧任务残留、旧节点回调或新卡片闪烁。
- 不以堆内存是否立即下降作为自动验收条件，因为垃圾回收时机不确定；验收的是强引用和观察/动画所有权已释放。

## 4. 执行与回归

1. 表单默认禁用与初始化顺序 → 构建检查 → 无脚本/延迟/正常交互测试。
2. 活动/完成状态分离 → 容器注销接入新闻render → 生命周期与分类/历史回归。
3. 执行 `npm run build`、`npm run check`、`npm test` 和 `git diff --check`。
4. 运行现有两组浏览器回归页，复核错峰、后台恢复、减少动态效果、FAQ开合与草稿、首页设备连线。
5. 在1920px、390px、360px检查表单正常/禁用两种状态的排版与焦点；无业务内容或布局调整时不扩大到重新校准全部PSD。
6. 交付修改清单、测试结果和未覆盖的实际浏览器限制；更新实施记录。

## 5. 方案 Review

| 风险 | 审查结论与修正 |
| --- | --- |
| 只禁用提交按钮 | 改为所有相关控件默认禁用，且先绑定处理器再启用；覆盖输入和提交退化路径 |
| 为修表单增加fieldset | 控件级disabled即可，避免更改网格结构和FAQ高度 |
| 入口失败仍显示可提交 | 默认HTML就是不可提交状态，不依赖失败处理器补救 |
| 只改GET为POST | 仍会实际请求，不能作为本问题修复 |
| Map直接换WeakMap | 会失去枚举能力；保留活动Map与完成WeakSet |
| 只清理完成节点 | pending观察和running动画仍能保留引用；三种状态全部注销 |
| 完成后删Map导致重复入场 | 完成WeakSet负责身份去重，清理临时容器时才显式重置 |
| 取消动画后旧回调继续写节点 | 复用现有控制器的任务身份校验，并验证过期观察回调 |
| 通过GC/堆大小判断泄漏 | 自动测试验证注册计数与所有权释放，不等待不确定的GC |
| 为测试暴露生产调试全局 | 使用小型生命周期模块的实例测试，加真实页面行为回归 |

结论：方案可以实施。两项修复独立推进，最终共同回归；无需先接入后端，也无需改变已确认的UI设计。
