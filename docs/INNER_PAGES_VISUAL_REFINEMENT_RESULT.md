# 内页视觉与动效调整结果

## 已实施

- 产品页按1920px PSD逐区校准标题、卡片、参数、应用条和留白；横幅设备图左侧从1150px移至1036px（原稿约1037px），保持原图比例。
- 16组技术参数保留；四组复合参数恢复独立的标签、数值和浅底子格。手机保留两列，单位可独立换行，尺寸值按空格自然换行。
- 公司页恢复两处山景。导出保留PSD底色、剪贴与透明度，不含标题或卡片文字；新增WebP合计约20KB。公司介绍、产业布局及优势区分别校准高度。
- 工艺页服务体系、团队卡片密度与区块比例校准；联系卡片恢复552px的桌面最小高度，咨询区起点回到原稿1136px；新闻详情减小正文段距和行距，保留真实完整文章。
- 桌面流程线和节点整组淡入，不再发生节点移动而线条静止的错位；第二节点保持默认强调。手机采用纵向节点和虚线连接，没有自动循环。
- 内页网格按实际视觉行错峰，同行延迟0/70/140ms，每行重新开始。时间线按左右方向轻移，手机短距离上移。沿用一次入场、后台恢复、焦点可见和减少动态效果机制。
- FAQ默认仅显示简短评价选项、补充意见入口、记录按钮与静态说明。选择负反馈展开意见，好评也可主动展开；隐藏与切换不清空草稿。展开意见前结束外层高度动画；重新开合先移除旧效果再测量自然高度。

服务页FAQ起点仍比原稿晚约13px，主要为前两区的自然文本高度及区块重叠差异；未通过裁切内容消除差异。其默认反馈区从273px缩小到83px。加入反馈后FAQ区仍比原稿高约97px；下载静态说明、咨询表单未发送提示也计入自然布局，不按原稿整页高度硬压。

新闻列表仅有现有真实静态记录，未用重复文章凑出原稿的多行列表；证书、PDF、正式二维码等仍为已注明的占位。无正式字体文件，继续使用现有字体回退；不同系统下换行和字形仍可能略有差异。

## 验证

- `npm run build`完成；`npm run check`检查14个JavaScript文件；`npm test`的12项测试通过；`git diff --check`通过。
- `tests/inner-browser.html`的5组浏览器回归通过：产品锚点与参数结构、真实动画延迟与终态、FAQ草稿/切换/记录、七页六种视口、减少动态效果的JS路径。
- 七页在1920、1280、761、760、390、360px下均无页面横向溢出；手机复合参数无卡片内溢出，流程方向正确。已加载图片无失败。
- FAQ浏览器检查包含快速切换问答、内外层动画交错、好评补充意见、记录提示与草稿保留；另外在390px视口实际填写意见并检查展开和溢出。
- 原有 `tests/motion-browser.html` 的5项首页真实动效回归全部通过，包括后台恢复、延迟入场、设备热点与连线对齐。
- 目视复核桌面参数、山景卡片、FAQ、联系卡片、新闻正文及手机流程/参数/反馈。
