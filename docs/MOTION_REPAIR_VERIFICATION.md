# 视频以外的动效修复：实施与验证记录

已实施方案阶段 1–7；正式视频按用户要求排除。PSD 版式及现有素材保留。

## 实施结果

| 问题 | 最终实现 |
| --- | --- |
| 入场被 CSS 覆盖 | 入场由独立动画控制器管理 opacity / translate / scale，组件悬停使用独立属性；标题子项分别注册，错峰仅存在于入场参数。 |
| 数字倒跳与错误中间值 | 仅两项百分比递增；屏下初始化为视觉零值，初始已可见的值保持终值；其余四项不改数值；隐藏终值节点随响应式字体预留宽度。 |
| 新闻悬停延迟 | 三张卡片 transition-delay 均为 0；实际入口悬停与键盘聚焦即时反馈。 |
| 热点切换跳变 | 四节点数值插值；唯一切换任务，最后选择优先；卡片按当前宽度预留最长文案高度；左侧点位从卡片底部出线。 |
| 弹窗与菜单关闭生硬 | 打开、关闭使用可取消的独立任务；Esc、关闭按钮、遮罩统一处理；退出后才关闭 dialog，恢复滚动和入口焦点。 |
| 首屏切换影响按钮 | 仅文字层切换；最长文案测量预留高度，CTA 保持稳定。 |
| 前后台与偏好变化 | 只管理本页面创建的动画；后台与减少动态效果进入终态，停止虚线，关闭任务仍完成清理。 |
| 平板横向溢出 | 导航在 960px 以下折叠；761–1050px 应用图标调整为 110px，修复原五列撑出页面的问题。 |

核心代码：`app.js`、`motion-core.js`、`motion.css`。HTML 添加文字/内容分层，未改变设备与定位父容器之间的结构。

## 浏览器实际验证

使用 Codex 内置浏览器操作页面与读取实际渲染状态。

- 检查过 360、390、430、760、761、960、961、1280、1440、1920px 代表宽度。发现的 761px 应用图标溢出已修复，并复验为页面宽度等于视口宽度；960/961px 导航切换正常。
- 连续选择热点 10 次：说明卡高度保持 221px（当次桌面宽度），最终文字、高亮和连接线端点一致；没有控制台报错或观察器循环警告。
- 新闻卡片实际计算样式：三张的过渡延迟均为 0s。
- 手机三份文案切换：CTA 顶部位置均为 339.5px、高度 44px、透明度 1（390px 视口的当次检查）。
- 手机菜单快速开、关、重开：最终状态与 aria-expanded 一致；导航链接关闭后可选择热点；Esc 关闭后焦点回到菜单按钮。
- 手机切回桌面：导航 display:flex，不残留 inert。
- 弹窗关闭按钮、Esc、遮罩分别验证；退出结束后 dialog 关闭、滚动锁释放，焦点回到打开入口。
- 图片全部加载，未观察到页面脚本错误。

## 验证边界

- 手机验证为模拟视口，未在真实 iPhone / Android 设备上验收触控手感。
- 尚未单独验证 Safari；不得将内置浏览器结果视为 Safari 通过。
- 减少动态效果的任务完成和清理逻辑已通过核心测试；本轮未切换系统设置验证完整浏览器链路。
- 未采集正式帧率录制；代码避免连接线逐帧读取布局，不能据此声明低端设备始终达到特定帧率。
- 视频保持原状态，未新增视频播放、服务器视频传输或自动播放逻辑。

## 后续 review 的三项修复与复验

本次修复错峰入场延迟阶段闪现、后台提前消耗待播放任务、设备移动期间热点与连线错位。

- 入场专用动画增加 backwards 填充；不改变其他切换或退出动画的填充行为。
- 后台收尾与减少动态效果分开：前者只完成 running，后者同时完成 pending；后台忽略可见性观察回调，前台主动检查当前可见的待触发内容。
- 设备处于 pending / running 时隐藏热点及连线；设备完成或因减少动态效果落到终态时自动恢复，保持原定位关系。
- `npm run check` 通过；`npm test` 共 8 项通过。
- 原生浏览器回归页 `tests/motion-browser.html` 共 5 项通过：待播放入场/计数保留、延迟期间透明度为零、前台恢复后完成、设备移动期间提示隐藏、设备完成后提示显示且锚点误差小于 1px。
- 浏览器回归直接加载真实首页和生产 CSS / JS；可见性变化在测试 iframe 内模拟，不改变生产代码的 `document.hidden`。该模拟不等同于真实手机或 Safari 实机验证。
