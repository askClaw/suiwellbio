## 2. 共用设计与组件

### 尺寸和布局

- 全部是 1920px 桌面稿，主要内容居中约 1200px，左右基准约 x=360/1560。
- 常规页顶部品牌条约 60px，主导航约 100px，内页横幅约 300px。
- `gy001.psd` 的整套页头从 y≈100 开始，上面多出约 100px 空白；这是画布偏移，不能作为所有工艺能力页面的真实顶部留白照搬。
- 公司介绍、参数、新闻等均使用真实文字与 CSS 布局；装饰背景和照片适合导出图片。不要把完整页面切成一张大图。

5. 页脚和快捷联系。
6. 圆角卡片、图标底色、按钮、虚线与步骤圆点。
7. 已修复的入场控制、悬停反馈、弹窗、移动导航、减少动态效果处理。

注意：PSD 多页沿用了“产品中心”的导航高亮，实际网站必须根据当前页面设置，不应原样复制。

### 3.5 新闻列表：news.psd

- 两个分类：公司新闻、市场活动。
- 3 列 × 2 行，共 6 张卡。
- 每卡：封面、日期、标题、摘要、阅读全文。
- 下方页码 1/2/3、下一页、末页。

重要：第二行重复第一行的 3 条内容，因此只有 3 组不同的列表样例，不能据此认定已有 6 篇完整稿件或 3 页新闻。

当前静态实现建议使用本地文章数组，分类与分页对真实数组运算；没有足够数据时不制造空白页或重复新闻。整卡语义应明确，可使用一个主链接覆盖标题/图片，避免多个嵌套链接和无效的空白点击区。

新闻动效复用已修复的入场、即时悬停；分类切换只更新列表区域，分页后定位列表标题；返回列表保留原分类和页码。

手机：卡片一列；分类保持明确选中态；页码适当收窄，不能只依赖横向拖动才能找到下一页。

## 5. 当前静态、后续接后端的安排

### 新闻

当前：

- 本地数据保留稳定 `id`，统一记录 `category`、`title`、`publishedAt`、`summary`、`cover`、`body`。
- 列表和详情读取同一份数据，防止同一篇文章在不同页面内容或日期不一致。
- 静态详情可以使用 `news-detail.html?id=…`，或生成独立文章文件；这是实现选择，不限定未来后台语言。
- 分类、分页、返回列表和下一篇基于真实静态数据工作；资料不足的文章不伪造正文。

后续：

- 将读取本地数据的部分替换为后端文章查询；稳定 ID、分类和展示字段继续沿用。
- 服务端渲染或接口读取均可，当前不预设 PHP、Node 或其他后端技术栈，也不先搭后台。
- 后端文章状态、图片管理和发布流程另行实施；当前 PSD 无后台界面。

### 服务支持页 FAQ 及反馈

当前：

- FAQ 数据独立保存，至少包含 `id`、`question`、`answer`、`answerVersion`，用于以后准确关联反馈。
- 问答采用键盘可操作的手风琴，稿中最后一条可作为初始展开项。
- 每条答案下预留“有帮助 / 没有帮助”和可选意见输入。这里是新增交互，应使用现有小按钮和青蓝色体系，不挤压原稿的问题标题。
- 反馈状态按 FAQ ID 区分；切换问题不应把反馈错误关联到其他条目。
- 静态演示只更新本页状态；如后续需要浏览器暂存可再增加，但不能把本地保存描述为已送达后台。
- 不显示真实的“服务器提交成功”或虚构汇总票数。

后续：

- 反馈最小数据建议：`faqId`、`answerVersion`、`helpful`、可选 `comment`；需要时附页面标识。
- 由后端接收、记录并提供管理端查看；接口成功、失败、重复点击和重试状态在接入时补齐。
- 当前无需收集设备指纹或额外个人资料，也无需为此先增加账号系统。

### 联系表单

用户本轮明确的后端范围是新闻与 FAQ 反馈；联系表单提交后端尚未单独确定。先按静态页处理，保留清晰的表单字段，避免将后端未接入误报为用户留言已送达。

## 6. 对当前首页代码的影响

当前 `app.js` 在顶层直接查询设备、热点、首页轮播等元素；直接给 7 个内页共用这份脚本，会因元素不存在而抛错。

实现内页前应先拆分：

- 通用：导航、页脚、内页横幅、入场控制、快捷联系、弹窗。
- 首页专属：首屏轮播、首页数据、设备热点与连接线。
- 内页专属：流程列表、FAQ 与反馈、新闻筛选/分页/详情、静态联系表单。

每个模块只在对应元素存在时初始化。沿用当前原生 ES Modules 和静态 HTTP 预览即可，无需仅因增加页面而引入框架。

导航应从首页锚点升级为真实页面链接；首页相关区块可继续保留锚点。咨询 CTA 最终指向联系页留言区，邮件和电话保持直接入口。

建议文件名：`product.html`、`process.html`、`service.html`、`about.html`、`news.html`、`news-detail.html`、`contact.html`。这能与现有参考代码的用途对应，避免 `gy001`、`new_detail001` 等设计文件名直接进入用户 URL。

## 7. 建议实施顺序

1. 提取共用布局与脚本，建立内页横幅和真实导航，回归首页现有动效。
2. 公司简介：验证通用内页和两地布局，复用首页最多。
3. 产品中心：建立核心单元、优势、参数与流程组件。
4. 工艺能力与服务支持：共用四段体系，完成时间线、FAQ、静态反馈和下载外观。
5. 新闻列表与详情：用统一静态数据跑通分类、分页、返回与下一篇。
6. 联系页：使用确认后的联系方式，完成静态表单。
7. 全站手机排版、键盘/触控与动效回归；分开记录静态演示、正式内容缺失与未来后端工作。

可先搭好全部静态结构，但正式内容与真实素材未确认的部分应列为待补，不替用户编造证书、新闻正文或产品承诺。
