# 静态表单与新闻动效注册修复结果

## 实施

- 生成器为联系表单和四条FAQ反馈表单的输入、文本域与按钮默认添加disabled及专用标记。搜索和其他业务按钮不受影响；无脚本时保留原生FAQ正文、电话及邮件入口。
- 每张表单先绑定同步提交拦截，再绑定其他交互，最后仅启用带标记的控件并写入ready状态。延迟初始化不清空已有值；恢复的负反馈会展开意见框。
- 新增 `entrance-registry.js` 管理注册生命周期：活动Map仅保存pending/running目标，完成身份用WeakSet去重。完成时释放活动强引用，同时保留一次入场语义。
- 新闻结果替换前限定容器注销旧目标，取消观察和动画、清除临时类/状态及完成身份；覆盖首次客户端替换、分类、分页和popstate路径。过期动画完成回调由现有控制器隔离，已注销目标的观察通知因没有活动状态而被忽略。
- 新闻render仅在URL确实需要规范化时调用replaceState，避免分类点击已经pushState后再重复写入同一URL。

## 验证

- `npm run build`完成；17个JavaScript文件语法检查通过；18项测试通过；`git diff --check`通过。
- 新增生命周期测试覆盖完成去重与释放、容器内三类目标注销、删除活动项时的遍历、取消后旧完成回调、100次替换时活动注册数量保持有界。
- 新增生成页面检查，确认两类表单的所有相关控件默认禁用，且有无脚本联系说明。
- `tests/static-lifecycle-browser.html` 的4组专项检查通过：
  - 联系与FAQ表单在无脚本沙箱、入口404、延迟加载三种情况下，于1920/390/360px检查默认不可输入/提交、不可聚焦、无原生导航；启用后保留已有值及评价，恢复负反馈时展开意见。
  - 联系表单错误/正确演示码、刷新、正常反馈记录均可用；提交不导航，未调用fetch/XHR。
  - 100次分类切换、popstate恢复和键盘聚焦正常；实际创建pending/running卡片后切换分类，旧节点的临时状态和动画已清理。
- 在独立真实新闻页，通过浏览器点击分类，再调用真实前进/后退，分别恢复市场活动/公司新闻及相应URL。
- 真实键盘Enter提交联系表单，页面保持 `contact.html#consultation`，显示格式检查通过且内容未发送。仅使用虚构测试值。
- 临时本地HTTP代理记录本轮请求：未发现携带表单字段的请求，也没有POST等非读取请求。日志保留在忽略目录 `.design/static-fix-requests.jsonl`，代理已在验收后关闭；原5173开发服务不受影响。
- 原有首页浏览器动效回归5项、内页浏览器回归5项均通过。内页基准测试在1920px视口运行，包含六种iframe宽度、FAQ草稿及减少动态效果路径。

## 边界与复现

浏览器检查页需要本地HTTP服务。专项检查默认可直接使用现有5173服务；请求审计是本轮额外使用的临时代理，不是运行页面所必需的依赖。截图为 `.design/static-fix-browser-results.png`。

自动专项测试通过popstate事件验证历史渲染；真实浏览器前进/后退另外使用可信点击验证，避免iframe合成点击的历史导航限制。未进行Safari或真实手机实机验收，也不以垃圾回收时机作为自动测试条件。
